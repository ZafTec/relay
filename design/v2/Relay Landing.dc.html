// 01 Object storage & background work

Files in.
Work underway.
URLs out.

Relay gives MCP clients and engineering teams durable object storage, observable background jobs, and signed delivery URLs — without routing file bytes through the application.

// 02 What Relay actually runs

STORAGE

S3-compatible object store

Any endpoint that speaks the S3 API. Bucket, prefix, and region are configuration, not a rewrite.

TRANSFER

Presigned PUT and GET

Clients transfer bytes directly against the store. The application signs, records, and stays out of the path.

HISTORY

Assets with immutable versions

A logical asset points at an ordered set of versions. Writes append; nothing is overwritten in place.

WORK

Durable background jobs

Workers lease queued jobs, report progress, and leave state and errors readable after the request ends.

No customer logos, uptime figures, or benchmark claims on this page — only what the system does.

// 03 Request to result

The request ends. The work continues.

A client asks for an upload URL, commits a version, and enqueues work. Relay hands the job to a worker and keeps the state where anyone with access can read it.

  1. 01 create_upload_url — signed PUT, scoped to one workspace prefix, expires in minutes.
  2. 02 commit_version — the uploaded object becomes v3 of a named asset.
  3. 03 enqueue_job — returns a job id immediately; the worker picks it up.
  4. 04 create_download_url — the generated version leaves as an expiring signed URL.

// 04 Versions

Every write keeps its predecessor

Assets are logical names. Versions are immutable rows underneath them, each with its own checksum, size, and creation time. Rolling back is selecting an earlier version, not restoring a backup.

  • ■ Checksums recorded at commit time
  • ■ Generated outputs land as versions, not new files
  • ■ Version identifiers are stable in URLs and job payloads

// 07 Usage & entitlements

Planned · not shipped

Limits that fail predictably

Entitlements are metered per workspace. When a limit is reached, new uploads and jobs are rejected with a typed error — reads and downloads keep working. No pricing is published yet.

// 08 Security & isolation

A workspace is the boundary, not a filter

OAuth only

Google and GitHub. No password storage in the initial product.

Scoped prefixes

Every object key sits under its workspace prefix. Signatures are issued for that prefix only.

Short-lived URLs

Upload and download URLs expire in minutes and are recorded when issued.

Superadmin is separate

Platform administration is a distinct permission, not workspace ownership.
